# scripts

Repo tooling. Repo-wide rules are in the [root AGENTS.md](../AGENTS.md).

- **`lint-comments [dir...]`** (`make lint`): fails on any comment in Go, shell (`.sh` or a shell shebang), Makefiles, YAML, Lua, SQL, `.txtar` scripts (only the script part, before the first `-- file --`), TypeScript and JavaScript (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`), CSS and Swift (`//`, `///` and nested `/* */`; multi-line `"""` strings are skipped). Only tool directives pass; in TypeScript that is a triple-slash `/// <reference ...>`, in Swift the `// swift-tools-version:` line. JSX text is not parsed, so put a `//` in text between tags in a string expression. It walks `.github/` but no other dot dir, and skips `vendor/`, `node_modules/`, the root `bin/`, every `dist/` (so the built app in `internal/serve/dist`), and Go files under `testdata/`. See [ADR 0044](../docs/adr/0044-no-comments.md). Its fixtures live in its `testdata/` as `*.<ext>.txt` so no other tool reads them.
- **`lint-agents`** (`make lint`): fails when the root `AGENTS.md` is over 150 lines (`-max n`), a scoped `AGENTS.md` has no `CLAUDE.md` symlink to it beside it, or a relative link in an `AGENTS.md` or `ARCHITECTURE.md` does not resolve. It skips `testdata/`, `.claude/`, `.git/`, `node_modules/`, `vendor/`, `bin/` and `dist/`. Fixtures are directory trees under its `testdata/`. See [ADR 0041](../docs/adr/0041-scoped-agents-md.md).
- **`tdd-check <base> <head>`**: what CI's `tdd` job runs. It covers added or changed `*_test.go` files and files under a `testdata/` dir (such as e2e `.txtar` scripts), each counted for the package that owns them. It runs them with `-tags integration`, so integration tests count too. First it fails when any non-merge commit in `base..head` changes tests and production code together; a commit whose subject starts with `refactor:` or `refactor(` and Markdown files are exempt; (ADR 0043). A moved and edited test counts in both checks, and the base run removes its old path and any test file the PR deleted. It ignores a Go test change when the file's Go tokens are unchanged, so whitespace and comments of either style don't count but whitespace inside a string literal does. In other testdata it ignores changes in whitespace amount, blank lines and, except in `*.golden` and `*.txt` fixtures where comment-shaped lines are data, `//` and `#` comment lines (ADR 0045). It skips `fakes_test.go`/`*_fake_test.go`. Web tests have parity with Go ([ADR 0048](../docs/adr/0048-web-toolchain-and-tdd-parity.md)): `web/**/*.test.ts(x)` and web `testdata/` count for the commit-order rule, and on base it runs `npm ci` in `web/` and then `npx vitest run` once per changed test file (or once for the directory owning changed web testdata); any that passes fails the job. A base without `web/package.json` counts as failing; a failed `npm ci` fails the job. Helpers under `web/src/test/` are exempt like port fakes. `TDD_WEB_INSTALL` and `TDD_WEB_TEST` replace the two commands, which its tests use to run without Node. Swift tests have the same parity ([ADR 0049](../docs/adr/0049-macos-app.md)): `macos/**/Tests/**/*.swift` count as tests, and on base it runs `swift test --filter <Target>.<File>` in `macos/` once per changed test file (the path under `Tests/` with `/` as `.` and no `.swift`), so a test file's name must match its suite's type name. A base without `macos/Package.swift` counts as failing. `TDD_SWIFT_TEST` replaces `swift test --filter`, which its tests use to run without Swift. Its tests are in `scripts/tddcheck`; they build throwaway repos and run the script on them. Run it locally on a clean tree to check a branch before pushing (it refuses uncommitted changes); it resolves both refs to commits first, so `HEAD` works, and on exit, pass or fail, it puts back the branch or commit you started on with a clean index.
- **`mutate`** (`make mutate`): runs `gremlins` on `domain` and `app`, failing below 80% efficacy. A package with no tests is skipped. Install with `go install github.com/go-gremlins/gremlins/cmd/gremlins@v0.6.0`.
- **`bench-hook.sh [bin]`**: times 200 `agentws hook` runs with the daemon up and down, prints p50/p95, and fails over budget (20 ms / 60 ms p95). Each side gets 20 discarded warmup runs and then three rounds of 200, and the lowest round's p95 is judged: a noisy neighbour only adds time, and one bad burst should not fail a fast hook. CI runs it with `BUDGET_SCALE=2` because its runners start processes about 3x slower.
- **`dev`** (`make dev [SEED=3] [FAKES=1]`): runs agentws from this checkout with its own `AGENTWS_HOME` (`/tmp/agentws-dev-$UID`) and tmux socket (`agentws-dev`), so the installed agentws and `~/.agentws` are untouched, and attaches to the dev layout. In the background it polls the Go sources each second; on a change it rebuilds, restarts the dev daemon and respawns the dev TUI pane on the new binary, and sessions survive as they do across any daemon restart. A failed build leaves the running instance alone and shows the first error on the dev tmux server; the full output goes to `dev.log` in the dev home. `SEED=n` runs `agentws debug seed n`; `FAKES=1` puts the e2e fake `claude` and `codex` first on `PATH` (they hold their pane and cost no usage). `scripts/dev stop` stops the watcher and the dev daemon. `AGENTWS_DEV_HOME` and `AGENTWS_DEV_SOCKET` move the instance; the home stays short and under `/tmp` because macOS caps Unix socket paths at 104 bytes. See [ADR 0039](../docs/adr/0039-dev-loop-and-build-handshake.md).
- **`screenshot <out.png> [COLSxROWS] < steps`**: renders a pane to PNG for a UI PR's body. It builds, starts a throwaway daemon and tmux server, runs `agentws tui --new-session` (or a `run <command>` step) with the launch dir set to the cwd, plays the stdin steps (`type <text>`, `key <tmux keys>`, `wait <s>`, `shot <file>` for an intermediate frame) and renders with `freeze` (`go install github.com/charmbracelet/freeze@latest`). A `run` step is split like a shell line (quotes kept, no globbing), each word is shell-quoted, and only a word that is exactly `agentws` becomes the built binary; blank lines are skipped. The pane runs with true color and is rendered on Latte's base (`SHOT_BACKGROUND`, default `#eff1f5`), since agentws paints no background of its own. Everything it starts (daemon, tmux server, pane, popups) runs with a throwaway `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `CLAUDE_CONFIG_DIR` and `CODEX_HOME` inside its temp `AGENTWS_HOME`, which is marked onboarded so the first-run walkthrough never shows; it builds before switching `HOME`. A step that sets any variable to the real `HOME` or a path under it is refused. Its tests are in `scripts/screenshottest`, with fake `agentws`, `tmux` and `freeze`. Run it from a demo folder tree and pass `run env HOME=<demo home> agentws ...` so no real paths show. Images live on the orphan `pr-assets` branch, not in main.
- **`web-screenshot < steps`**: renders the web app for a PWA PR's body. It starts the Vite dev server with the fake API (`web/fake-api.ts`: `hello` reports `v1` and build `v0.12.0+demo`; pairing accepts `ABCD2345`, answers `ZZZZZZZZ` with 429 and anything else with 401; `/api/v1/stream` sends a demo state with every group, both limits and two queued sends on the running `s3`; `GET …/messages` answers every session with a chat of tool rows (done with a test result, failed, running) and Markdown, and its older page after 5 s so a shot can catch the loading row; send, unsend and interrupt answer success; and with `AGENTWS_FAKE_STREAM=offline` drops the first stream after 300 ms and refuses the rest, for the offline state; with `AGENTWS_FAKE_STREAM=late` closes the first stream with 4401 after 300 ms while `GET /api/v1/workspaces` still answers, so the app keeps its login and reconnects; with `AGENTWS_FAKE_STREAM=revoked` does the same but `GET /api/v1/workspaces` answers 401, for the pairing screen with its signed-out note) on 127.0.0.1 (`WEB_SHOT_PORT`, default 5199) and drives Playwright's Chromium from stdin steps: `device <Playwright device>` (default `iPhone 15`), `mode browser|installed` (installed sets `navigator.standalone`), `goto <path>`, `fill <label>=<text>`, `click <button name>`, `see <text>`, `wait <ms>`, `shot <file>` (full page, relative to the cwd). `device` and `mode` start a fresh browser context. Playwright is pinned in `web/package.json`; install its browser once with `cd web && npx playwright install chromium`. Push the images to the orphan `pr-assets` branch like `screenshot`'s.
- **`install.sh`**: installs a release and copies `nvim/lua` and `nvim/plugin` to `${XDG_DATA_HOME:-~/.local/share}/agentws/nvim`. To try a release build: `goreleaser release --snapshot --clean`, serve `dist/` with `python3 -m http.server`, and run `scripts/install.sh` with `AGENTWS_DOWNLOAD_BASE`, a temp `AGENTWS_INSTALL_DIR` and a temp `XDG_DATA_HOME`. See [ADR 0040](../docs/adr/0040-first-run-walkthrough.md).
