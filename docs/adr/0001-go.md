# ADR 0001: Build in Go

Status: accepted, 2026-09-30.

## Decision

Build `crew` in Go as a single binary.

## Why

- **Hook latency:** hooks run on every agent tool call. A Go binary starts in about 5 ms, while Node and Python take 50–150 ms, which would slow every agent turn.
- **Most work is shelling out:** git, gh, tmux, lsof, osascript. Go's `os/exec` and goroutines make that simple, and a faster language gains little here.
- **Mature TUI stack:** Bubble Tea, Lip Gloss and chroma cover the sidebar, the diff view and syntax highlighting.
- **Agents write most of the code:** Go's small language, fast compiles (seconds) and strict formatting keep agent-written code consistent and quick to iterate on.
- **Distribution:** static binary, no runtime, `brew install` later.

## Rejected

- **Rust (ratatui):** faster rendering and stronger types, but slower compiles and slower iteration. Our hot paths are subprocess-bound, so Rust's speed wouldn't show.
- **TypeScript (Ink) / Python (Textual):** the startup cost fails the hook budget, and both need a runtime installed.
- **Swift:** fits the future native macOS client, but not a TUI. The macOS client can talk to the same daemon over the socket.
