# web

The phone app: a PWA that `agentws serve` embeds and serves at `/` (ADR [0046](../docs/adr/0046-remote-app.md), toolchain and decisions in ADR [0048](../docs/adr/0048-web-toolchain-and-tdd-parity.md)). Repo-wide rules are in the [root AGENTS.md](../AGENTS.md); they apply here too, including no comments and test first.

## Commands

- `npm ci` once, then `npm test` (Vitest, jsdom) and `npm run typecheck`.
- `make web` (from the repo root) builds into `internal/serve/dist`. The shell is written as `app.html`; the committed `index.html` there is the placeholder a Node-less `go build` embeds. Then `make build` gives a binary that serves the app.
- `npm run dev` runs Vite; `AGENTWS_API=http://127.0.0.1:7420 npm run dev` proxies `/api` (and the stream) to a running `agentws serve`; add `AGENTWS_API_INSECURE=1` to accept its `--self-signed` certificate. `npm run fake` uses the fake API in `fake-api.ts` instead. The dev server binds every interface and accepts `.ts.net` hosts.
- `npm run icons` redraws the PNG icons in `public/` from `public/icon.svg` with Playwright.
- `scripts/web-screenshot` (see [scripts/](../scripts/AGENTS.md)) takes the PR screenshots.

## Layout

- `src/api.ts`: the HTTP client. Every error is an `ApiError` with the HTTP status and a code: the server's `error.code`, else one derived from the status (`401` → `unauthorized`, `429` → `rate_limited`), `network` when the server cannot be reached.
- `src/App.tsx` picks the screen: the session list when `localStorage` holds `agentws.auth`, Add to Home Screen in a browser tab, pairing in the installed app. `AppEnv` carries everything from the browser (fetch, storage, display mode, URL hash, host, user agent), so tests pass fakes.
- `src/build.ts` and `src/sw.ts`/`src/sw-cache.ts`: the worker is registered as `/sw.js?build=<hello build>` and caches into `agentws-shell-<build>`; `checkBuild` reloads a page whose worker build differs from `hello`'s. `vite.config.ts` writes the built file list into `sw.js`.
- `src/stream.ts`: the `/api/v1/stream` client and its types (Go field names as the goldens pin them). `StreamClient` sends the token first, applies diffs (`applyDiff`), backs off 1 s doubling to 30 s (reset once a state arrives), and stops on 4401 (status `unauthorized`); `onFrame` passes every frame (transcripts, watch errors) and `send` writes `watch`/`unwatch` frames while `live`. With `visible` set (`AppEnv.visibility`, `document.visibilityState` in `main.tsx`) it sends `{"visible":bool}` once live, on every `visibilitychange` (`visibilityChanged`) and `{"visible":true}` every 30 s while shown, so the daemon does not push to a phone that has the app open. `useStreamClient` owns one client per token, `useStream` reads its `StreamSnapshot` (`status`, `state`, `retryAt`). The app holds one client in `App` and shares it with every screen; a screen that watches a session re-sends its `watch` when the status goes back to `live`.
- `src/api.ts` also has the authed session calls (`Authorization: Bearer <token>`): `messagesPage`, `sendMessage`, `unsend`, `interrupt`. `src/transcript.ts` keeps one session's messages: pages and `transcript` frames merge by `id` (a later copy replaces the earlier in place, so a finished tool call updates its row), ordered by `cursor`; a `reset` starts over and makes `before` unknown (`null`, so the next older load asks for the newest page); `toolRow` splits the tool name off `Tool.Summary` and `testResult` reads a go test, Vitest/Jest, pytest or cargo summary from the output. Diff counts are not in a `Message`, so tool rows do not show them.
- `src/screens/Session.tsx` is the chat: the header (name, `where`, harness and model, context left, a state chip, Interrupt while running or asking permission, behind a confirmation), the log, and the composer. The log loads the newest page (50), then sends `watch` with the newest cursor it holds, and again whenever the stream is `live` again; it sends `unwatch` when it closes. Scrolling near the top (or the top row's button) loads the page before `before` and keeps the reading position by adding the height it grew to `scrollTop` (iOS Safari has no `overflow-anchor`); the top row keeps one height while it says loading, so it never shifts the log. New messages scroll to the bottom only while the reader is there. The composer sends with `POST …/messages`; the button says Queue while the session is running or asking permission. The session's queued sends (stream `sends`) sit above it with Edit (unsend, then the text goes back into the composer) and Drop (unsend); a send that already went out (`not_found`) says so. The end of the log (`Chat`'s `children`, `.chat-end`) holds the permission card (`PermissionCard`): while the session's state is `permission` it fetches `GET …/prompt` (again whenever `since` changes, i.e. the session re-enters permission) and shows the text with one button per choice (`POST …/answer {choice}`). A 409 `stale`, a `not_found`, or the stream leaving `permission` turns it into "This prompt is gone" and nothing is sent; a prompt with `raw` and no choices shows "Couldn’t read this dialog" and the raw pane text, no buttons. The composer is disabled while the state is `permission`. Tests: `npm test -- Permission`.
- `src/sessions.ts`: grouping by attention (Needs you: permission then waiting, longest first; Working; Done: unread first; Idle; ended sessions left out), time in state, and the limits rows. `src/route.ts`: `#/sessions/<id>` opens a session (push notifications use the same URL), `#/new` is the new session form (`screens/NewSession.tsx`: workspace, work item checked through `/work-items/resolve` after 350 ms, first prompt, agent, model, effort; the choices are remembered in `agentws.new` in `localStorage`, the workspace defaulting to the daemon's last used; a launch error, including a setup recipe's output, shows in the form and success opens `#/sessions/<id>`), anything else the list.
- `src/push.ts` and `src/sw-push.ts`: Web Push. `AppEnv.push` (`browserPush(window)` in `main.tsx`, `FakePush` in tests) wraps `Notification` and `pushManager`. Settings reads the real state on open: `PushEnv.subscribed()` (the worker registration's `pushManager` holds a subscription) when permission is granted, shown as "Notifications are on for this device" with Turn off (`disablePush`) instead of Enable; the server is not asked, since it has no endpoint that reports a device's subscription. `enablePush` runs only from the Settings button: it asks for permission first (iOS needs the user's tap for that), then `GET /api/v1/push/key`, subscribes with that key, and posts the subscription to `/api/v1/push/subscribe`. The worker's `push` handler shows `{"title","body"}` tagged by session (never silently: missing fields fall back to `agentws` / `needs you`); `notificationclick` focuses an open window of the app and navigates it to the push's `url` (`/#/sessions/<id>`, same-origin paths only), else opens one. Settings also says, as static text, that pushes are held while the owner types at the terminal and not sent while the app is on screen. Sign out first calls `POST /api/v1/push/unsubscribe` and unsubscribes the browser (best effort), then forgets the token. Tests: `npm test -- Push` and `npm test -- Settings`.
- `#/settings` shows Settings (server, this device, Enable notifications, sign out); a tab bar under the session list and Settings switches between them.
- `src/screens/`: one component per screen. `src/theme.css`: the TUI's Latte palette as CSS variables, IBM Plex Sans and JetBrains Mono from `@fontsource`.
- `src/test/`: test helpers (`FakeServer`, `MemoryStorage`, the Vitest setup). tdd-check treats them like port fakes.

## Tests

- Text colors must reach 4.5:1 on the background they sit on and tap targets 44 px; `src/theme.test.ts` checks the token pairs and the `min-height` of the tappable classes, so add a new pair or class there when you use one.
- Test through the rendered screen with Testing Library (roles, labels, text) and through module inputs and outputs; fake the network with `FakeServer`, never mock modules.
- `*.test.ts(x)` files count for tdd-check like Go tests: commit them before the code, and they must fail on base.
